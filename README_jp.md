# ミニエディター

## 検索の除外条件

検索 / 置換ダイアログの「検索時、除外条件」で、一致部分と重なる検索結果を飛ばせます。
入力欄は「検索する文字列」→「検索時、除外条件」→「置換後の文字列」の順に並びます。
検索・前へ・マーカー・プレビュー・置換・すべて置換・マーカー付き置換に共通で適用し、
空欄にすると解除します。

「正規表現として検索する」をオンにし、検索を `\n`、除外条件を
`<br><br>\n|>\n` にすると、タグ直後の改行を除外できます。
複数条件は `|` で区切ります。先頭の `-` は除外指定にはなりません。
CRLF の文字列では、両方の条件の改行を `\r?\n` と指定してください。

正規表現をオフにした場合、除外欄は一つの文字列として扱います。
正規表現と大文字・小文字の設定は検索欄と共通です。「単語全体」は検索条件にだけ適用します。
除外は一致した文字の範囲に働き、行全体を除外する指定ではありません。
文字幅のない一致は除外範囲にしません。選択範囲・表示範囲だけを検索する場合は、
その範囲内で除外条件を判定します。入力内容はダイアログを閉じても今回の起動中は保持しますが、
再起動時の保存・復元は行いません。

## 色プリセットとリスト枠変換

- 文字色と背景色の名前・CSS値は、アプリケーションと同じフォルダにある
  `color_presets.json`で管理します。文字色のショートカットも同じJSONで変更できます。
- 開発版ではプロジェクト直下のJSONを使います。EXE版では、JSONがない場合に同梱済みの
  初期設定を`regex-pad.exe`の隣へ自動作成します。編集後はRegexPadを再起動してください。
- `text_colors`は`color: ;`、右クリックの文字色メニュー、文字色ショートカットに共通で使われます。
  `background_colors`は`background-color: ;`の候補に使われます。
- 編集用JSONが壊れている場合は上書きせず、その起動では同梱済みの初期設定を使います。
- 段落分割メニューの「リストを枠囲みに変換」は、選択したMarkdownリストまたは既存の
  WordPressリストブロックを一つの`wp:html`枠へ変換します。
- WordPressテーマがリスト記号を非表示にしても読めるよう、`ul` / `ol`のマーカーではなく、
  「・」または「1.」などを文字として出力します。既存の「リスト変換」もそのまま利用できます。

ミニエディターは、Windows 11向けの軽量なポータブルテキストエディターです。

インストーラー、管理者権限、レジストリ変更、オンラインサービスを使わず、フォルダ一つで動かせることを目標にしています。

## CSS / HTML / WordPress 文法チェック

文法チェックは、貼り付け前・保存前の事故を減らすための軽量linterです。
ブラウザやWordPress本体と同じ完全なパーサではありませんが、記事HTMLを壊しやすい典型的なミスを見つけることを目的にしています。

- 未登録のHTMLタグや、HTML属性のtypo候補を検出します。
- HTMLの`style`属性、`<style>`要素、単独の`.css`ファイルを同じCSS辞書で検査します。
- 波括弧の過不足、閉じていないコメント・引用符・丸括弧、全角記号、コロン不足、セミコロン不足候補を検出します。
- 未登録またはtypoの可能性があるCSSプロパティ・単位、不正な登録キーワード、16進カラー、単位不足、プロパティ重複、一部の数値範囲・型の誤りを検出します。
- `href` が `<p>` に付いている場合など、属性名は正しくてもタグとの組み合わせが不自然な場合に警告します。
- 未登録のWordPressコアブロック名を検出します。
- WordPressブロックコメント内の `{}` パラメータがJSONとして読めない場合に警告します。
- 同梱のWordPressコアブロック属性辞書を使って、想定外の `{}` パラメータを警告します。
- 一部のWordPressブロック属性について、`level` の文字列指定、booleanの文字列指定、paragraphのalign値typoなど、型・値の不自然さを警告します。
- WordPressブロックの開始・終了の不一致、終了コメント抜け、`wp:list-item` などの閉じ忘れを検出します。
- WordPressブロック内でHTMLタグが完結しているかを確認します。
- 通常のHTMLファイル全体に加え、WordPressブロックが混在する文書のブロック外HTMLも検査します。
- 余分なインライン終了タグ、`h1`～`h6`の開閉不一致、段落・リンクの入れ子、段落内のブロック要素、直接の親が`ul`・`ol`・`menu`ではない`li`を検出します。
- `<!-- wp:latest-posts /-->`などの自己完結コメントに対応し、後続ブロックの開閉数や入れ子に影響させません。
- `list-item`と`list`、`column`と`columns`の直接の親子関係、リスト・カラムに許可される子ブロック、段落内の子ブロックを検査します。
- 段落ブロックのルートは`p`1個、見出しブロックのルートは見出し要素1個として検査します。コメントやエスケープ済みのタグ例を要素として数えません。
- 段落自身の一部の文字装飾・色の`style`と、指定された色・サイズのプリセットクラスを、ブロックコメント属性と照合します。本文中のインライン装飾は別に検査します。テーマCSS、任意の独自クラス、余白・枠線、Gutenbergの保存HTML全体の再生成までは照合しません。
- 文書全体とブロック境界の検査でHTMLタグの台帳を共有し、同じ行の同一指摘は1回だけ表示します。
- `</div>` 抜け、閉じ順の逆転、`</p>` 前のインラインタグ閉じ忘れなどを検出します。
- separatorブロックに不要な `<code>` が混入した場合など、原因が同じ連鎖エラーは代表的な警告に抑えます。
- `<code>...</code>` 内のエスケープ済みコード例は、表示用テキストとして扱えるように過剰検出を避けます。
- 文法チェック結果はエディタタブごとに保持します。タブを切り替えると、結果ダイアログは選択中タブの最新かつ有効な結果を表示し、タイトルに対象ドキュメント名を表示します。
- 最後のRegexPadウィンドウを閉じた時、文法チェック結果の一時フォルダも削除します。

## タグスニペット

- タグ候補は `dictionaries/html_dict.json`、`dictionaries/markdown_dict.json`、
  `dictionaries/wordpress_html_dict.json` に候補を分けて管理。
- 右クリックメニューからタグやスニペットを選び、カーソル位置へ挿入。
- よく使うインラインHTMLは、`Ctrl+B` で `<strong>`、`Ctrl+U` で `<u>`、`Ctrl+Alt+1` から `Ctrl+Alt+7` で7色の文字色 `<span>` として選択範囲を囲めます。赤文字は既存互換として `Ctrl+Alt+R` でも使えます。
- HTML、Markdown、WordPress HTMLの記事作成向けスニペットを挿入できます。
- WordPress向けスニペットは、記事ブロックの境界を壊さないよう保守的に扱います。
- 右クリックの段落分割メニューから、選択したMarkdown表やリストを内蔵 `wp_conv_core` 経由でWordPressブロックに変換できます。外部コンバーターのパス設定や環境変数は不要です。

## 今後の方針

- 日本語Typoや表記ゆれチェックは、辞書と設定切替を準備した後に追加予定です。
- WordPressコアブロック / 属性辞書は、公式資料と実例に合わせて保守的に更新します。

## 注意

正規表現エンジンには、Python標準ライブラリの `re` を使います。

検索だけでは本文を変更しません。本文が変更されるのは、ユーザーが置換またはすべて置換を実行した時だけです。

正しくない正規表現はエラーとして表示し、本文は変更しません。
